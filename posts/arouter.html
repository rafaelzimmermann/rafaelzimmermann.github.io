arouter: Pick a Grade, Not a Model

October 11, 2026 3 min read

Model selection became a chore. I kept a mental map of which subscription quota resets when, repointed tools between providers when one ran dry, and occasionally burned pay-per-token keys because I forgot. So I wrote arouter, a quota-aware router in Rust.

The idea is simple: my tools stop asking for a model and ask for a grade instead — A+, A, or B. arouter serves each request from whatever makes sense at that moment: the subscription with the healthiest quota, a warm local engine, or, only if I allow it, the cheapest paid API that fits the budget. Every response says where it went (X-Arouter-Upstream, X-Arouter-Grade).

It talks to upstreams for quota directly — OpenRouter's key endpoint, x-ratelimit-* headers from responses it already proxies, a 429 as ground truth — and scores providers accordingly. Windows about to reset enter drain mode, so expiring quota gets spent instead of wasted. On-demand APIs sit behind stacked spend guards (daily, monthly, pace, per-request caps — tightest wins), with atomic admission so concurrent requests cannot oversubscribe a cap. Failing models cool down; stalled upstreams hit deadlines and fail over.

Any OpenAI-compatible client works:

./target/release/arouter serve --config config.example.toml  # 127.0.0.1:3929

curl -s localhost:3929/v1/chat/completions \
  -d '{"model":"A+","messages":[{"role":"user","content":"hi"}]}'

Anthropic-wire clients like Claude Code work too, and there's an htop-style live monitor plus Prometheus metrics if you want to watch it decide.

I have been running it as my daily driver for everything. It is v0.1 — the routing logic is exercised by a black-box test rig, but it is still a young piece of software.
