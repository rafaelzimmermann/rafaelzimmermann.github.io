aitop: htop for AI Usage

October 11, 2026 2 min read

Between Codex, Claude, Copilot, z.ai, OpenRouter, and DeepSeek, I had no single place to see what my quota was doing on any of them. Each provider has its own way of reporting usage, if it reports at all. So I wrote aitop: htop for AI usage, one Rust binary.

It shows rolling quota windows, reset countdowns, spending budgets, usage pace, and balances for the providers above, alongside local engine state — Strata and Ollama, plus local session activity. A few details got care because they annoyed me first:

  • Reset times include an absolute local clock (resets in 2h30m @ 16:58), so they can be compared with what provider CLIs print.
  • A window that rolls over from ~100% explains itself (5h window just reset (was 100% at 13:36)) instead of looking stuck at 0%.
  • Panel titles distinguish live provider data, local estimates, and stale cached snapshots.

It auto-detects existing Codex and Claude credentials and GitHub CLI authentication, and shows only the panels that are actually configured. There is plain-text and JSON output for scripts, and you can zoom into a single provider or use the two-column overview.

git clone https://github.com/rafaelzimmermann/aitop.git
cd aitop
cargo install --path . --locked
aitop

That is the whole idea: the number that matters, for every provider, in one terminal.
