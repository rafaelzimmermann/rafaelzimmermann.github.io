Parrot: Giving My Linux Desktop a Voice

October 3, 2026 5 min read

The interaction I wanted was small: highlight some text, press a shortcut, and have the computer read it aloud. A little window should let me pause or change the speed, then disappear when it finishes. That became Parrot, a Rust utility for Hyprland.

The repository is called Parrot; the executable is hypr-speak. Its default shortcut is Alt+Escape. Speech runs locally, using either espeak-ng or an optional Piper neural voice.

First, hear it

Download the audio. Transcript: “Hello! I am Parrot. Highlight some text, press your shortcut, and I will read it aloud. Pause whenever you like, or change the speaking speed. Your words stay on your computer.”

This is synthesized output from the application. Voice installation downloads the engine and model first; once installed, synthesis happens on the computer. The model's provenance is linked in the repository's demo notes.

A small pipeline with two speech engines

Parrot reads Wayland's primary selection, falling back to the regular clipboard. It cleans the text, limits its length, and divides it into chunks. A worker synthesizes those chunks into PCM audio, rodio handles playback, and an egui overlay provides the controls.

The boundaries are deliberately simple. Selection handling does not need to know which voice is speaking. Playback receives samples and a sample rate. Both speech engines implement the same TtsEngine interface, so the UI does not have to know whether the audio came from a C library or a subprocess.

espeak-ng is the compact option: the application calls its system library through Rust's foreign-function interface. It is intelligible and has a distinctly synthetic voice. Piper provides the neural option, using a separate executable and an ONNX model. The demo above uses Piper.

That choice has a cost. The current Piper backend starts a process for each sentence, which can introduce gaps. Keeping an engine alive is a possible improvement, but it adds a longer-lived process and a more involved cancellation story. For this first version, the simpler boundary made the implementation easier to inspect.

Speed control changes synthesis parameters instead of accelerating already-generated audio. When the speed changes, the current sentence restarts. The overlay closes automatically after playback ends, and Escape dismisses it immediately.

The installer was part of the application

A shortcut-driven utility depends on its desktop integration. The installer checks native dependencies, scans supported Hyprland configuration patterns for a conflicting shortcut, builds the release binary, and backs up the configuration before appending a binding and window rules.

One detail matters more than it looks: the binding uses the absolute executable path. A compositor's environment may have a different PATH from an interactive shell. A command that works in a terminal can otherwise fail when launched by a shortcut.

The installer also handles classic configuration files and a supported native Lua configuration form. That is still a limited parser. Arbitrary Lua expressions, includes, and more complicated configuration arrangements need further work. The review records those limits rather than treating a few successful fixtures as proof that every configuration is covered.

And, because a project called Parrot should at least contain a parrot, the installer now prints a small ASCII bird.

The useful part of the review

Before sharing the repository, I asked for an architecture and code-quality review, fixes, and a written progress record. Several findings were more interesting than cosmetic cleanup.

  • Global state needs an enforced owner. espeak-ng has process-global state. A worker convention alone did not stop callers from constructing two engines. An atomic ownership gate now rejects a second active instance.
  • A dry run must avoid writes. The installer previously still invoked the build during a dry run. That path now skips building and does not require an existing release binary.
  • Clipboard input needs a boundary. Reading arbitrary MIME data into an unbounded buffer was unnecessary. The reader now requests text and caps the bytes it consumes.
  • Playback outlives synthesis. The worker could exit after queueing the last sentence, making later speed restarts ineffective. It now stays available during final playback and advances the sentence display with playback sequencing.

The installer review also found malformed generated Lua and shortcut comparisons that depended on modifier order. The regression checks now parse generated Lua and verify that reordering modifiers cannot hide a conflict.

The local verification finished with 36 passing Rust tests, 41 installer checks, a successful release build, and clean formatting and strict Clippy checks. An Ubuntu CI workflow is included. Those checks are useful evidence, while live desktop testing and broader configuration coverage remain on the release checklist.

Try it on Hyprland

You need Rust 1.92 or newer and the native development dependencies listed in the README. From there:

git clone https://github.com/rafaelzimmermann/parrot.git
cd parrot
./install.sh --dry-run
./install.sh

For the neural voice used in the demo:

./install.sh --voice en_US-lessac-medium

You can also generate audio without opening the overlay or reading the clipboard:

hypr-speak --engine piper --text "Hello from Parrot" --wav demo.wav

Linux distribution compatibility and desktop compatibility are separate questions here. The README includes Ubuntu/Debian build dependencies, but selection capture requires Wayland data-control protocols. Hyprland is the intended desktop; GNOME, KDE, and X11 selection capture are not currently supported or verified. Headless WAV rendering avoids that desktop dependency.

What comes next

Parrot is an early release. The remaining work includes live playback validation, stronger config parsing, verified download checksums, subprocess cancellation, and more distribution testing. Those items live in the review and release checklist.

The source is available under the MIT license at github.com/rafaelzimmermann/parrot. If you try it, a report with your compositor version, speech engine, and the command that failed would be especially useful.
